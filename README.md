# 拼多多百货店铺 0 → 1 · 亏损诊断

> 三个人合伙开店 **3 个月**（实测，2025.02–2025.05），上架 **30+ SKU**（实测），因品类竞争与流量不足主动关停，最后以亏损收场（实测，金额未记录、不披露）。
>
> 案例页（完整推理过程）：**https://big-niuNiu929.github.io/work/pdd-store.html**

这个仓库不是「开店教程」，是一次失败留下的**诊断结构**：四个维度、每维回答同一个问题——如果重来，动哪一项会有不同结果。

---

## 先说位置

三个人合伙，我负责运营执行：上架、售前客服、动态报价、社群引流。

不是负责人，也不是牵头人。货源、库存、物流在第二个人那里；店铺统筹、活动报名、流量投放和财务在第三个人那里。关停是三个人一起决定的，复盘报告由我主笔。

把「我开了家店」写成开头是最容易的，也是最假的。

## 三个月里做了什么

| 动作 | 具体做法 | 结果 |
|---|---|---|
| **上架合规** | 标题、类目、属性、图片逐条对平台规则，宁可慢一点也不拿扣分换速度 | 30+ SKU 从 0 到可售，全程零违规扣分（实测） |
| **售前客服** | 尺寸、能不能便宜、什么时候发——答得快不算本事，答得和商品页一致才算 | 每次改价改库存后先同步话术再回话 |
| **动态报价** | 价格跟着平台活动和进货成本走，改一次留一行记录 | 谁在什么时候把哪个价格改成什么，能查 |
| **社群引流** | 把有意向的人拢到一个池子，上新/活动时推一次 | 只解决「看不看得到」，解决不了「买不买」 |

## 结果（能核对的三项）

| 项目 | 数字 | 标记 | 口径 |
|---|---|---|---|
| 上架 SKU | 30+ | 实测 | 2025.02–2025.05 上架数，日用百货；是上架口径，不是销量 |
| 运营周期 | 3 个月 | 实测 | 止于三人共同决定的主动关停 |
| 结果 | 亏损 | 实测 | 具体金额未记录，不披露 |

GMV、订单数、客单价、获客成本**一个都没留下**——表格在那里，没人填。所以这里不做任何金额或倍数推算。这是这个项目最大的教训，也是「先建表」被写进方法的原因。

## 四维诊断模型

见 [`docs/亏损诊断模型.md`](docs/亏损诊断模型.md)。四个维度：**选品 / 定价 / 流量 / 获客成本**。

每一维都要回答「重来动哪一项会有不同结果」，答不上来的说明它只是感受，不是原因。

## 不做什么

- 不放后台经营数据、店铺名、供应商与合伙人信息
- 不把失败包装成「躬身入局的故事」
- 不做没有记录支撑的金额与倍数推算
